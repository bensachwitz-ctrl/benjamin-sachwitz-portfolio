## What this project is

Ben's portfolio site - a **multi-page static site** (vanilla HTML/CSS/JS, Tailwind via CDN). **Zero build step.** Deployed to Vercel; one `vercel deploy --prod --yes` ships it. Vercel `cleanUrls:true` serves each `*.html` at a clean path (`/career` → `career.html`).

**Architecture (since 2026-05-30 multi-page split):**
- **Shared assets** linked by every page: `/styles.css` (all CSS, extracted from the old inline `<style>`) + `/app.js` (ALL chrome + the full arcade engine, extracted verbatim - one big IIFE; do NOT split it). Reference them with a `?v=` cache-bust query (assets are cached immutable by `vercel.json`) - bump the version when you edit either.
- **Pages**: `index.html` (home - most sections + arcade *teaser*), `arcade.html` (`/arcade`, full 39-game arcade), `career.html` (`/career`), `projects.html` (`/projects`, websites+work), `apps.html` (`/apps`, app cards w/ images), `booking.html` (`/booking`, auto-opens the booking modal).
- Every page shares the same chrome markup (nav, `#ambientBg` glyph layer, footer, `#bookingModal`) so `app.js` wires it identically; `app.js` is `getElementById`-guarded so absent elements just no-op (e.g. arcade code is dormant on non-arcade pages).
- **Nav** links are cross-page (`/career`, `/projects`, `/apps`, `/arcade`, `/booking`, `/#about`); the left section-rail exists on home only.
- Pages were generated by `repo-review/build-pages.py` (slices `index.html` by `<section id>` and assembles each page). Pre-split single-file backup: `index.backup-premultipage.html`.

## Conventions you must follow

1. **Edit `index.html` directly.** Don't introduce a build step, a bundler, or a framework. The whole point is shipping speed.

2. **Mode-toggle (`html[data-mode]`)** - when adding new copy or sections, decide whether it should be mode-aware. If yes, add one of:
   - `class="mode-bio" data-bio-underwriter="…" data-bio-builder="…"` for paragraphs
   - `class="mode-bio-html" data-bio-html-underwriter="…" data-bio-html-builder="…"` if you need `<strong>` / `<em>`
   - `class="mode-eyebrow" data-eyebrow-{underwriter,builder}="…"` for micro-labels
   - `class="mode-title" data-title-{underwriter,builder}="…"` for subsection titles
   - `class="mode-underwriter-only"` or `class="mode-builder-only"` for visibility-only swaps (add `.block-mode` for `display: block`)

3. **Never break the reveal failsafe.** All `.reveal` elements are guaranteed to appear within 3 s regardless of JS or scroll position. If you add a new reveal-coupled animation, don't override the `animation` CSS property on `.reveal` - extend it.

4. **Hero title must always render.** `.hero-title .hero-line` has `opacity: 1` baseline. Don't remove that.

5. **Booking modal: two tabs.** Live Calendar (Cal.com inline embed) + Request a Time (multi-step form). Both must remain functional. If you add a third tab, follow the `.bmtab` + `data-bmode-pane` pattern.

6. **`CAL_CONFIG`** at the top of the booking script controls the Cal.com calLink. Don't hardcode `bensachwitz/30min` anywhere else - use the config.

7. **Chapter numbering** - sections carry roman numerals (I–IX). When adding a chapter, update:
   - The `eyebrow` text on the section heading ("Chapter 0X · Name")
   - The `chapter-num` div on the right side of the section header
   - Nav (desktop + mobile)
   - `section-rail` aria-labels
   - JSON-LD `BreadcrumbList` in the `<head>`

8. **No emojis in source unless Ben requests.** Brand voice is Carolina Executive - restrained typography over decoration.

9. **Failsafes you should preserve:**
   - Loader: hard-cap at 2.5 s via `setTimeout(hideLoader, 2500)`
   - Reveal: CSS `revealFailsafe` keyframe at 2.5 s + JS failsafe at 3 s
   - Cal.com: 6 s elevation timer on `.booking-cal-fallback`
   - Mode hydrate: `applyModeCopy` runs once at script start
